# Lavender組み込み要件

SES補助システムを既存管理画面Lavender（2way Manage system）の機能として組み込むための要件を示す。

- 作成日: 2026-08-04
- 更新日: 2026-08-21（最新実装のメニュー、ルート、権限制御を反映）
- ステータス: 実装準拠

## 1. 基本方針

| 項目 | 内容 |
|------|------|
| 追加先 | Lavender（React） |
| バックエンド | thyme（Spring Boot） |
| 位置づけ | FUKURO2.0とは別の大項目「SES」 |
| 認証 | Lavender既存のログイン機構を利用 |
| 共通UI | 既存AppBar、Drawer、Container、テーマを利用 |
| 権限 | ロール×機能の定義を一元化し、利用可能なメニューとルートを制御 |

独立したフロントエンド基盤、ログイン、共通レイアウトは作成しない。

## 2. サイドバー

`src/index.tsx` のログイン中メニューに、FUKURO2.0メニューの後、ログアウトの前へSESメニューを配置する。

```text
FUKURO2.0
  （既存メニュー）

SES
  案件メール一覧
  要員メール一覧
  メンバー一覧
  マッチング一覧
  提案管理一覧
  スキルマスタ
─────────────────────
  ログアウト
```

- 見出しは既存と同じ `Typography variant="overline"` を利用する
- FUKURO2.0配下の既存項目は変更しない
- SES項目は権限定義に基づいて表示する
- スキルシートは独立メニューにせず、メンバー詳細のタブに配置する

## 3. 画面とルーティング

ルーティングは `src/index.tsx` の `<Switch>` に集約する。具体的な画面項目は
[画面設計](../design/screen-design.md) を正とする。

| 機能 | パス | 用途 |
|------|------|------|
| 案件メール一覧 | `/project-mail` | 抽出案件一覧、検索、取込実行・履歴 |
| 案件メール詳細 | `/project-mail/:id` | 抽出内容と原文の確認・編集 |
| 要員メール一覧 | `/staff-mail` | 抽出要員候補一覧、検索、取込実行・履歴 |
| 要員メール詳細 | `/staff-mail/:id` | 抽出内容と原文の確認・編集 |
| メンバー一覧 | `/member` | メンバー検索・一覧 |
| メンバー新規登録 | `/member/new` | 基本情報とスキルの登録（既存スキルシートの紐付けは行わない） |
| メンバー詳細 | `/member/:id?tab=info\|skill-sheet\|matching\|proposal` | 4タブの統合詳細 |
| メンバー編集 | `/member/:id/edit` | 基本情報、スキル、シート紐付けの編集 |
| スキルシート新規 | `/member/:memberId/skill-sheet/new` | 対象メンバーのシート作成 |
| スキルシート編集 | `/member/:memberId/skill-sheet/:id/edit` | 対象メンバーのシート編集 |
| マッチング一覧 | `/matching` | 同一案件グループを含む結果一覧 |
| メンバー側結果 | `/matching/:projectId/:personnelId` | 案件とメンバーの対比・判定結果 |
| 候補者側結果 | `/matching/:projectId/staff/:staffCandidateId` | 案件と要員候補の対比・判定結果 |
| 提案管理一覧 | `/proposal` | 提案進捗一覧 |
| スキルマスタ | `/skill-master` | 登録待ちスキルとマスタ管理 |
| 案件詳細 | `/ses/projects/:id` | 候補メンバーを含む案件詳細。メニュー外導線 |

### メンバー詳細タブ

タブ順とクエリ値を固定する。

| 表示順 | ラベル | `tab` 値 |
|-------:|--------|----------|
| 1 | 基本情報 | `info` |
| 2 | スキルシート | `skill-sheet` |
| 3 | マッチング | `matching` |
| 4 | 提案状況 | `proposal` |

不正または未指定の `tab` 値は `info` として扱う。マッチング一覧と提案管理一覧は、遷移先に対応する値を付ける。

### 廃止した画面・パス

- 独立スキルシート一覧・詳細（`/skill-sheet` 系）
- 案件の独立一覧（`/ses/projects`）
- 旧案件・要員モックパス（`/project`、`/staff`）
- 旧要員パス（`/ses/personnel` 系）

ブックマーク互換が必要な場合のみリダイレクトを設け、新規導線には使用しない。

## 4. 画面間導線

- 案件／要員メール一覧 → 各メール詳細
- メンバー一覧 → メンバー詳細の基本情報
- マッチング一覧 → メンバー詳細のマッチングタブ、候補者側結果、案件詳細
- 提案管理一覧 → メンバー詳細の提案状況タブ
- メンバー詳細のスキルシートタブ → 新規作成／編集／PDF表示
- メンバー詳細のマッチングタブ → 現行の承認／見送り／差し戻し／提案作成
- スキルマスタ → 登録待ちスキルの仕分け、マージ、再照合

承認と候補者昇格を廃止する案（C8）は未適用であり、現行導線には残す。

## 5. 実装規約

- React 17、TypeScript、Material-UI v4、Redux Toolkitという既存構成に合わせる
- 既存テーマと共通コンポーネントを優先し、ページ単位で別デザインシステムを持ち込まない
- SES REST APIの認証トークンは既存ログイン状態から付与する
- ルート、メニュー、権限制御の定義を可能な限り一元化する
- パスはケバブケースを原則とする
- APIエラー、ローディング、空状態を各一覧・詳細画面で表示する

## 6. 影響範囲

### Lavender

- `src/index.tsx`: SESメニュー、ルート、権限制御
- `src/views/ses/**`: メール、メンバー、提案、案件詳細、スキルマスタ
- `src/views/matching/**`: マッチング一覧・結果
- `src/views/skillSheet/**`: メンバーに紐づくスキルシート編集・印刷
- `src/api/ses/**`: SES REST APIの型とクライアント

### thyme

- SES API、メール取込、マッチング、提案、スキルマスタ
- SES用DDLとデータ移行／再照合処理
