# スキルシート要件

今回確認した自社スキルシートExcelの構造をもとに、Web化にあたっての要件を整理する。

- 作成日: 2026-08-03
- 更新日: 2026-08-21（メンバー詳細タブへの統合と最新画面を反映）
- ステータス: 実装準拠

---

## 1. 基本方針

Excelの見た目をそのままWeb上に再現しない。

情報を以下の単位に分けて管理する。

1. 基本情報
2. スキル
3. 資格
4. 職歴（画面上の文言は「**経歴**」に統一。2026-08-05変更）
5. 自己PR

DBを正本とし、作成・編集はすべてブラウザ上で行う。氏名や希望条件などの個人属性は
メンバー編集を正規の入力画面とし、スキルシート編集は「スキル・資格」「経歴」「自己PR」の3タブで構成する。

> 当初はExcelを初期インポート用の入力アダプターとする方針だったが、
> **Excelインポートは中止した**（2026-08-16決定。10章参照）。既存Excelの内容はブラウザ上での新規作成で移行する。

---

## 2. 基本情報

メンバー情報として管理し、スキルシート表示にも利用する項目は以下とする。
これらはスキルシート編集画面には重複表示せず、メンバー登録・編集画面で変更する。

| 項目 | 備考 |
|------|------|
| 社員番号 | 半角英数字、4桁以内。重複不可（重複時は保存エラー） |
| 氏名 | |
| フリガナ | |
| 性別 | 必須 |
| 生年月日 | 必須 |
| 年齢 | DBへ固定値として保存せず、生年月日から算出する |
| 居住地 | 必要な粒度に分割（下記参照）。都道府県・市区町村は必須 |
| 最寄駅 | |
| 最終学歴 | |
| 希望単価 | 下限・上限の2値（万円/月）。下限 <= 上限を検証する |
| 希望勤務地 | |
| リモート希望 | |
| 勤怠提出元 | **シート単位で1値のみ保持**（2026-08-12決定。下記参照） |
| 最終更新日時 | 保存時に年月日と時刻（分まで）を記録する |

### 補足

- **年齢はDBへ固定値として保存しない。** 生年月日から算出する。
- 住所全文が案件マッチングに不要な場合は、居住都道府県、市区町村、最寄駅など必要な粒度に分ける。
- 就業状況は基本情報として直接入力させず、職歴の「現在参画中フラグ」と終了年月から算出する。
- 転職意向はMVPの入力項目から外す。
- 社員番号は半角英数字のみ・4桁以内とする（当初の「ハイフン可」から変更）。
- 氏名、フリガナは入力例を表示し、姓と名の間に半角スペースを入れる運用を促す。

### 勤怠提出元（2026-08-12 シート単位に変更）

- 当初は職歴ごとに保持する方針だったが、用途が「最新の稼働状況の把握」のみであるため、
  **スキルシート単位（基本情報）で1値のみ保持する**ことに変更した。過去現場ごとの値は持たない
- 選択肢は「上位会社」「参画中メンバー」。任意入力（未設定可）
- 一覧画面では**管理者のみ**列表示・検索の対象とする

---

## 3. スキル

以下の情報を管理する。

- スキル名
- カテゴリ
- 経験期間
- 最終利用時期
- 表示順
- 備考

### 補足

- MVPでは、経験期間や最終利用時期の**自動集計は必須としない**。
- 職歴上の使用技術から自動集計する方式は将来対応とする。
- 最終利用時期は `yyyy-mm` 形式で入力する。ハイフンは自動挿入し、利用者は半角数字のみ入力できればよい。

---

## 4. 資格

以下を管理する。

- 資格名
- 取得年月
- 備考
- 表示順

### 入力順

資格の入力欄は以下の順序とする。

1. 資格名
2. 取得年月
3. 備考

取得年月は `yyyy-mm` 形式で入力する。ハイフンは自動挿入し、利用者は半角数字のみ入力できればよい。

---

## 5. 職歴

職歴は繰り返し追加可能な構造とする。

職歴1件あたり、以下を管理する。

- 表示順
- **経歴区分**（経験者 / 未経験。2026-08追加）
- 開始年月
- 終了年月
- 現在参画中フラグ
- プロジェクト名
- 業務内容
- 役割
- チーム人数
- 使用環境
- 使用技術
- 担当工程
- 備考

> 勤怠提出元は職歴の項目から**基本情報（シート単位）へ移動した**（2026-08-12決定。2章参照）。

### 担当工程の候補

- 要件定義
- 基本設計
- 詳細設計
- 設計構築
- 製造
- テスト
- 運用保守
- サポート

### 経歴区分と経験年数の算出

- 各職歴に経歴区分（**経験者 / 未経験**）を持つ
- 一覧画面等に表示する経験年数（経験月数）は、**経歴区分が「経験者」の職歴のみを合算**して算出する
- 終了年月が未設定の職歴は、本日までの期間として計算する

### 就業状況の判定

就業状況は職歴から自動判定する。

| 条件 | 就業状況 |
|------|----------|
| 現在参画中フラグあり、終了年月なし | 稼働中 |
| 現在参画中フラグあり、終了年月あり | 稼働中（終了予定あり） |
| 現在参画中フラグなし | 待機中 |

検索条件にも「稼働中」「待機中」「稼働中（終了予定あり）」を用意し、完全一致で絞り込む。

### 年月入力

- 開始年月、終了年月は `yyyy-mm` 形式で入力する。
- ハイフンは自動挿入し、利用者は半角数字のみ入力できればよい。
- 現在参画中フラグの有無にかかわらず、終了年月は入力、編集できる。
- 現在参画中フラグを切り替えても、入力済みの終了年月は消さない。
- 開始年月と終了年月の両方が入力されている場合、開始年月は終了年月以前でなければならない。

### 操作要件

職歴は、以下ができる構成を想定する。

- 追加
- 編集
- 削除
- 並び替え
- 複製

## 6. 自己PR

- 改行可能なテキスト形式とする
- MVPではリッチテキストエディタは利用しない

## 7. 下書き保存

スキルシート編集中は、入力途中の内容を下書きとして保持する。

### 保存方式（2026-08-04 決定）

| 項目 | 決定 |
|------|------|
| 保存先 | **DBに保存する**（ブラウザローカルではない） |
| 保持単位 | **ユーザー×スキルシート単位**。同一ユーザーが同一シートを編集中の下書きは1件 |
| 保持形式 | 編集画面の入力内容をJSONで丸ごと保持する |
| 保存中の表示 | **画面右下に小さく固定表示**する |

管理者が他人のスキルシートを編集した場合、下書きは編集した本人のものとして保持する。

### 自動保存

- スキルシート編集画面を開いている間、1分おきに下書きへの自動保存を実行する
- 入力内容が未変更の間、および正式保存の実行中・復元確認の表示中は自動保存しない
- 下書きには、スキル、資格、経歴、自己PRなど、編集画面で入力中の内容を保存する
- 下書き保存は正式保存ではなく、編集途中の復元用データとして扱う
- 自動保存は同一レコードへの上書きとする

#### 適用範囲（2026-08-04 決定）

| 状態 | 自動保存 |
|------|---------|
| 新規作成中（まだ一度も保存していない） | **行わない** |
| 手動保存後の再開（既存スキルシートの編集） | **行う** |

新規作成の入力途中は下書きを作らない。利用者が「保存する」で正式保存し、
以降その スキルシートを編集する場面から自動保存が有効になる。

#### 失敗時の扱い（2026-08-04 決定）

- 自動保存が失敗しても、画面上にエラーを表示しない
- 次回の自動保存タイミング（1分後）で**黙って再試行する**
- 「保存する」ボタンによる正式保存の失敗は自動保存と区別し、従来どおりエラーを表示する

### 正式保存時の扱い

- 「保存する」ボタンを押下した場合、現在の入力データを正式データとして保存する
- 正式保存が完了したら、該当スキルシートの下書きは破棄する
  - 破棄は**サーバー側**が行い、**ユーザーを問わず該当シートの下書きを全件削除する**。
    別の管理者が同じシートを編集中だった場合、その下書きも破棄される（意図した仕様）
- 正式保存後は、保存前の正式データを現在の入力データで上書きする
- 最終更新日時は保存時点の `yyyy-mm-dd hh:mm` 形式で記録する。秒は記録しない

### キャンセル時の扱い

- 「キャンセル」を押下した場合、該当スキルシートの下書きは破棄する
- キャンセル時は、入力途中の内容を正式データへ反映しない

### 下書き復元

- 下書きが残っている状態でブラウザを閉じる、画面遷移するなどして編集を中断した場合、次回スキルシート編集画面を開いたときに下書き復元確認のポップアップを表示する
- ポップアップで「はい」を押下した場合、下書きの内容を入力欄に反映する
- ポップアップで「いいえ」を押下した場合、下書きを破棄し、正式保存済みデータを入力欄に表示する

## 8. 入力補助・入力チェック

### 自動整形とフォーカス移動

- 生年月日は `yyyy-mm-dd` 形式で入力する。
- 年月項目は `yyyy-mm` 形式で入力する。
- ハイフンは入力中に自動挿入し、利用者は半角数字のみを連続入力できればよい。
- 生年月日、年月項目は、必要桁数の入力が完了したら自動的に次の入力欄へ移動する。

### 日付妥当性チェック

- 生年月日、年月項目は、入力完了時および保存時に妥当性を検証する。
- `13月`、`32日` など存在しない年月日を入力した場合は、該当欄に留め、エラーを表示する。
- 職歴の開始年月、終了年月は、開始年月 <= 終了年月であることを検証する。
- 条件を満たさない場合は保存できない。

---

## 9. PDF

外部提出、メール添付、印刷用としてPDFを利用する。

### 実装方式（2026-08-05 確定・実装済み）

- 専用PDF生成基盤は使わず、**印刷用HTML＋ブラウザの印刷／PDF保存機能（`window.print`）で対応する**
- 詳細画面の「PDF表示」ボタンで印刷を起動する。画面表示は変えず、**印刷時のみ職務経歴書の帳票レイアウト（A4縦）に切り替える**
- 帳票上の氏名は**イニシャル表記**に変換して出力する（例: 「佐藤 健一」→「K.S」）
- 経歴件数・文字量に応じてフォントサイズを自動調整する
- 個人情報の公開範囲やマスキング機能は将来対応とする（変更なし）

---

## 10. Excelインポート（中止）

**Excelインポートは中止した**（2026-08-16決定）。

- 理由: 利用頻度が少なく、開発工数を回収できない恐れがあるため
- 取り込み画面・一覧からの導線は実装から削除済み
- 既存Excelの内容は、ブラウザ上での新規作成で移行する
- 将来再検討する場合の前提整理は社内資料として保存済み
- Excelへの再出力を行わない方針は従来どおり

---

## 11. 確定済み事項・残課題

### 確定済み（実装反映）

- スキルのカテゴリ体系: **言語 / FW / DB / OS / インフラ / ツール** の6分類
- 勤怠提出元の必須入力条件: **任意入力（未設定可）** とする
- PDFレイアウト: 職務経歴書帳票（9章参照）
- Excel関連の未確定事項: インポート中止により消滅

### 残課題

- 一覧の検索・絞り込みのAPI側移行（現状は画面側で絞り込む暫定実装。
  サーバー側ページングと併用のため、絞り込みが表示中のページにしか効かない既知の課題がある）
- E2Eテストの拡充

スキルシートは**メンバー詳細内の「スキルシート」タブへ統合済み**。
新規作成は `/member/:memberId/skill-sheet/new`、編集は
`/member/:memberId/skill-sheet/:id/edit` を使用する。独立一覧・詳細画面は新規導線に使用しない。
