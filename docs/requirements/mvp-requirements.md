# MVP要件定義

SES補助システム MVP（Minimum Viable Product）の要件をまとめる。

- 作成日: 2026-08-03
- 更新日: 2026-08-21（最新のLavender／thyme実装と画面モックを反映）
- ステータス: 実装準拠

画面名、導線、項目は最新実装を正とする。実装状況の詳細は
[実装現状の記録](../development/implementation-status.md) を参照する。

---

## 1. 実現方式

本システムは独立サービスではなく、既存管理画面Lavender（2way Manage system）のSES機能として追加する。
認証、AppBar、Drawer、ContainerはLavender既存機能を利用し、APIはthyme、データはSES用MySQLスキーマで管理する。

SESメニューは次の6項目とする。

- 案件メール一覧
- 要員メール一覧
- メンバー一覧
- マッチング一覧
- 提案管理一覧
- スキルマスタ

スキルシートは独立メニューにせず、メンバー詳細のタブから参照・作成・編集する。

## 2. MVPで目指す状態

1. 営業メールから案件・要員候補を抽出し、重複を防いでDBへ登録できる
2. メンバー情報とスキルシートをブラウザで一元管理できる
3. 案件とメンバー／要員候補の適合度を確認できる
4. マッチング結果から提案を作成し、進捗を追跡できる
5. 未登録のスキル語を整理し、マッチングに利用するマスタを育成できる

## 3. 対象機能

### 3.1 案件メール管理

- 案件一覧の検索、絞り込み、ページング
- 案件詳細とメール原文の表示、抽出結果の編集
- 取り込みの手動実行、進捗ポーリング、直近結果、実行履歴
- IMAPからの取得、Message-IDによる重複排除、メール分類と構造化抽出
- 1通に複数案件が含まれる場合の分割登録

画面パスは `/project-mail` と `/project-mail/:id` とする。案件そのものの詳細は
`/ses/projects/:id` に残し、マッチングや提案から到達する。

### 3.2 要員メール管理

- 要員候補一覧の検索、絞り込み、ページング
- 要員候補詳細とメール原文の表示、抽出結果の編集
- 確認済み／非表示の管理
- 案件メールと共通の取り込み実行、進捗、履歴表示
- 1通に複数要員が含まれる場合の分割登録

画面パスは `/staff-mail` と `/staff-mail/:id` とする。

### 3.3 メンバー管理

- 一覧、検索、絞り込み、新規登録、編集、詳細
- メンバー詳細に次の4タブを表示
  1. 基本情報
  2. スキルシート
  3. マッチング
  4. 提案状況
- 一覧から詳細へ遷移し、遷移元に応じて `tab` クエリで初期タブを指定
- 要員候補からメンバーへ昇格する現行導線

パスは `/member`、`/member/new`、`/member/:id`、`/member/:id/edit` とする。

### 3.4 スキルシート管理

- メンバー詳細タブでの表示、新規作成、編集
- スキル／資格、経歴、自己PRの3タブ編集
- 経歴登録時の「経験者」「未経験者」選択
- 下書きのDB保存、復元、削除
- 印刷用HTMLとブラウザ印刷によるPDF出力
- スキルシート単位の勤怠提出元（任意入力）

ExcelインポートとExcel再出力は行わない。詳細は
[スキルシート要件](skill-sheet-requirements.md) を参照する。

### 3.5 マッチング管理

- 案件とメンバー／要員候補の双方向マッチング
- マッチング一覧、同一案件の結果グルーピング、検索・絞り込み
- 総合点、スキル点、条件係数、各条件の判定理由を表示
- スキル、単価、稼働形態、開始時期、年齢、商流、外国籍、個人事業主を判定し、勤務地は判断材料として表示
- NG条件を候補から除外し、WARNING数に応じて条件係数を適用
- 要員候補のメンバー昇格と、マッチングの承認／見送り／差し戻し
- 承認済みの組み合わせから提案を作成

現行実装には昇格・承認操作がある。これらを廃止して提案ステータスへ一本化する案（C8）は今後の変更候補であり、現行仕様にはまだ適用しない。

### 3.6 提案管理

- 提案一覧は閲覧を中心とし、行選択でメンバー詳細の提案状況タブへ遷移
- 提案1件を1カードで表示し、6段階の進捗ステッパーを表示
- 提案先、宛先、面談回数、現在ステータス、次回アクション日、メモを表示・更新
- ステータスは提案準備中、提案メール送信済、面談済、結果、採用、見送り、取下げ、参画。面談回数は別項目で保持する
- 面談回数はステータスとは別に保持

### 3.7 スキルマスタ

- 正式スキル名と別名の検索・管理
- メール抽出で見つかった登録待ちスキルを、登録、別名、対象外へ仕分け
- マージと既存データの再照合

## 4. 対象外

- 高精度なAIマッチング、提案結果を用いた機械学習
- Excelインポート、Excel再出力
- 請求、契約、勤怠、営業管理全般
- 複雑な承認ワークフロー、詳細な変更履歴比較
- メールへのPDF自動添付、リアルタイムメール受信

## 5. メール取り込み方式

画面上の「メール取り込み」から手動実行できる。設定により定期実行も可能だが既定は無効とする。
認証情報とAPIキーはリポジトリへ保存せず、外部設定または環境変数から取得する。

## 6. 完成条件

- [x] 案件・要員メールを取得、分類、抽出し、重複なくDBへ登録できる
- [x] 取り込みの進捗と履歴を画面で確認できる
- [x] 案件・要員候補を一覧、詳細画面で確認・修正できる
- [x] メンバーを登録・編集し、4タブの詳細画面を確認できる
- [x] スキルシートをブラウザで作成、参照、編集、PDF表示できる
- [x] マッチング一覧と結果詳細を確認し、現行の承認・提案導線を操作できる
- [x] 提案の進捗、次回アクション日、面談回数、メモを管理できる
- [x] 登録待ちスキルを整理し、既存案件を再照合できる

E2Eテストや既知の運用課題は完成条件とは別に、
[実装現状の記録](../development/implementation-status.md) で管理する。

## 7. 確定事項

| 項目 | 決定 |
|------|------|
| フロントエンド | Lavender既存（React 17 / TypeScript / Material-UI v4 / Redux Toolkit） |
| バックエンド | thyme（Spring Boot） |
| DB | SES用MySQLスキーマ |
| 認証・共通レイアウト | Lavender既存機能を利用 |
| 権限 | 管理者／一般。許可範囲を一元管理し、利用可能なメニューと画面を表示 |
| スキルシート | メンバー詳細タブへ統合。DBを正本とする |
| PDF | 印刷用HTML＋ブラウザ印刷 |
| Excel | インポート・再出力とも対象外 |
| パス | ケバブケース。既存互換が必要なパスは個別に維持 |
