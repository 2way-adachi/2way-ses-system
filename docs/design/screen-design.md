# 画面設計

Lavenderに実装済みのSES画面と、`gh-pages` の画面モックを基準に画面構成を整理する。

- 作成日: 2026-08-03
- 更新日: 2026-08-21
- ステータス: 実装・モック反映済み
- 実装の正: Lavender `src/index.tsx`、`src/views/ses/**`、`src/views/project/**`、`src/views/staff/**`
- モックの正: `gh-pages` ブランチ `index.html`

> 本書は古い独立スキルシート画面や5メニュー構成ではなく、2026-08-21時点のLavender実装を優先する。
> 将来変更として修正タスクリストC8にマッチングの昇格・承認操作の削除案があるが、現行実装とモックにはまだ反映していない。

## 1. 共通レイアウトとメニュー

Lavender既存のAppBar、Drawer、ContainerとMaterial-UI v4を利用する。SESメニューは次の6項目。

```text
SES
  案件メール一覧
  要員メール一覧
  メンバー一覧
  マッチング一覧
  提案管理一覧
  スキルマスタ
```

スキルシートは独立メニューを持たず、メンバー詳細から閲覧・作成・編集する。

## 2. ルート一覧

| 画面 | ルート | 備考 |
|---|---|---|
| 案件メール一覧 | `/project-mail` | 管理者はメール取り込み可能 |
| 案件メール詳細・編集 | `/project-mail/:id` | 抽出結果と元メールを2カラム表示 |
| 要員メール一覧 | `/staff-mail` | 管理者はメール取り込み可能 |
| 要員メール詳細・編集 | `/staff-mail/:id` | 抽出結果と元メールを2カラム表示 |
| メンバー一覧 | `/member` | カード一覧 |
| メンバー新規登録 | `/member/new` | メンバー属性とスキルを登録。既存スキルシートの紐付け欄は表示しない |
| メンバー詳細 | `/member/:id?tab=` | 4タブ構成 |
| メンバー編集 | `/member/:id/edit` | 基本属性・希望条件・ログインユーザー紐付けを編集。スキルシート紐付け操作は表示しない |
| スキルシート新規作成 | `/member/:memberId/skill-sheet/new` | 保存後はメンバー詳細へ戻る |
| スキルシート編集 | `/member/:memberId/skill-sheet/:id/edit` | 3タブ構成 |
| マッチング一覧 | `/matching` | メンバーと未昇格候補を表示 |
| マッチング結果 | `/matching/:projectId/:personnelId` | メンバーとの結果 |
| 候補マッチング結果 | `/matching/:projectId/staff/:staffCandidateId` | 未昇格候補との結果 |
| 提案一覧 | `/proposal` | 行押下でメンバー詳細へ |
| スキルマスタ | `/skill-master` | 登録待ちとマスタ一覧 |
| SES案件詳細 | `/ses/projects/:id` | メニュー外。各画面から到達 |

廃止済み: `/skill-sheet`、`/skill-sheet/:id`、`/skill-sheet/new`、`/skill-sheet/:id/edit`、`/skill-sheet/import`、`/ses/projects`。

## 3. 案件・要員メール

### 3.1 メール取り込みパネル

両一覧の上部に管理者向け共通パネルを表示する。

- メール取り込み実行、実行中表示、多重起動防止
- 直近実行日時、状態、取得・案件・要員件数
- 履歴ダイアログ（実行単位＋アカウント単位）
- 実行中はポーリングし、完了後に一覧を再取得

### 3.2 案件メール一覧・詳細

一覧はフリーワードとステータスで絞り込み、案件名、必須スキル、勤務地、単価、開始時期、送信元、受信日時、ステータスを表示する。

詳細は左に「抽出結果（編集可）」、右に「取り込み元メール（読み取り専用）」を表示。案件名、詳細、必須/尚可スキル、単価、勤務地、稼働形態、開始時期、面談回数、年齢、商流、個人事業主、外国籍可否、状態を編集する。

### 3.3 要員メール一覧・詳細

一覧はフリーワードで絞り込み、イニシャル、年齢、性別、最寄駅、所属、単価、稼働開始、スキルを表示する。

詳細は案件と同じ2カラム構成。イニシャル、年齢、性別、最寄駅、所属、単価、稼働開始時期、スキルを編集する。

## 4. メンバー

### 4.1 メンバー一覧

- カード形式、PCは3列
- 区分: すべて／社員／BP
- 検索: 氏名・最寄駅・保有スキル
- 稼働状況: すべて／稼働可／稼働中／対応不可
- 表示: 氏名、区分、所属会社、状態、スキルと経験年数、最寄駅、稼働可能時期
- 新規登録と詳細への導線

### 4.2 メンバー詳細

ヘッダーは氏名、社員/BP・所属会社、稼働状態、編集ボタン。タブ順は次のとおり。

| 順番 | 表示名 | `tab`値 |
|---:|---|---|
| 1 | 基本情報 | `info` |
| 2 | スキルシート | `skill-sheet` |
| 3 | マッチング | `matching` |
| 4 | 提案状況 | `proposal` |

#### 基本情報

社員番号、氏名イニシャル、フリガナ、性別、生年月日、外国籍区分、個人事業主、最寄駅、住所、学歴、稼働可能時期、希望単価・勤務地、リモート希望、勤怠提出元、所属会社、メモ、保有スキルを表示する。

#### スキルシート

- 未作成時は新規作成ボタン
- 作成済みは公開状態、社員番号、最終更新、PDF表示、編集を表示
- 基本情報、スキルサマリー、やりたい技術、資格、経歴、自己PRをタブ内表示
- 印刷時のみ職務経歴書レイアウトへ切り替える

#### マッチング

案件名、点数、一致スキル、不足スキル、状態、操作を表示。行押下でマッチング結果、案件名リンクでSES案件詳細へ遷移する。現行実装では見送り操作と未提案バッジを表示する。

#### 提案状況

提案1件を1カードで表示する。

- ステッパー: 提案準備中／提案メール送信済／1回目面談済／…／N回目面談済／結果。案件の想定面談回数ぶん
  面談ステップを省略せず表示する。結果確定後は「結果」を採用または見送りへ置き換え、採用時だけ末尾に参画を追加する
- 最終面談済み時の状態変更は結果を選択させず、採用または見送りを直接選択する
- 左: 提案先、宛先、面談回数、現在状態、次回アクション日、面談日時、提出日
- 右: 次のステップまたは見送りだけを選べる状態変更、面談日時、実施済み面談回数、次回アクション日、メモの更新フォーム
- 変更がある場合のみ更新ボタンを有効化
- マッチング控えを折りたたみ表示

### 4.3 メンバー登録・編集

基本情報、個人属性（住所・希望条件）、ログインユーザー紐付けを管理する。保有スキルはスキルシートで編集する。
2026-08-31更新: 新規登録・既存メンバー編集のどちらにも、スキルシートカード・選択ダイアログ・紐付け解除を表示しない。編集画面ではスキルシート候補一覧APIも呼び出さない。
新規登録の`skillSheetId`はnull固定。編集保存では詳細取得時の`skillSheetId`をそのまま送信し、既存の紐付けを維持する。データやAPIの紐付け機構自体は削除しない。
新しいスキルシートはメンバー保存後、メンバー詳細のスキルシートタブから作成し、保存時に自動で紐付ける。
既存シートの編集もメンバー詳細のスキルシートタブから行う。編集画面の紐付け欄削除は実装済み・モック未反映（修正タスクリストAP）。

## 5. スキルシート編集

メンバー配下の専用ルートで表示し、次の3タブを持つ。

1. スキル・資格
2. 経歴
3. 自己PR

基本情報タブは廃止し、個人属性はメンバー編集で管理する。スキル・資格タブの先頭に「やりたい技術」を置き、スキルマスタから最大5件を選択する。経験スキルとは別管理とする。経歴追加は「経験者」「未経験」を分ける。既存編集は下書き自動保存、復元確認、未保存離脱確認に対応し、新規作成中は自動保存しない。

## 6. マッチング

### 6.1 一覧

状態と「承認済みで提案未作成のみ」で絞り込む。案件名、メンバー/候補名、点数、一致・不足スキル、状態、操作を表示する。未昇格候補には候補バッジと昇格ボタンを表示する。

### 6.2 結果

ヘッダーに案件×メンバー/候補、総合点、スキル評価、条件係数、判断状態、未提案バッジ、現行実装の承認ボタンを表示する。

本文は2カラム。

- 左: 必須/尚可スキルと条件軸の案件・要員対比表。劣位側を強調
- 右: 同一案件グループの重複メール。案件メール詳細と経由メールを選ぶ提案ボタン
- 右下: 見送りボタン

候補から提案する場合はイニシャル名でメンバーへ自動昇格してから提案を作成する。

## 7. SES案件詳細

案件一覧は持たず、各画面からリンク到達する。「案件情報」「候補要員」「提案状況」の3タブ。候補からマッチング結果、提案からメンバー詳細の提案状況へ遷移する。

## 8. 提案一覧

メンバー名（部分一致）、ステータス、完了案件表示で絞り込む。案件ID・メンバーIDの検索欄は表示しない。
状態は提案準備中、提案メール送信済、N回目面談済、結果、採用、見送り、参画（取下げは既存データのみ）。
行押下でメンバー詳細の提案状況タブを表示する。

## 9. スキルマスタ

### 登録待ちスキル

未対応/却下済みを切り替え、頻度・初出・最終出現を表示。判断ダイアログで新規正規スキル登録、既存スキルの別名登録、却下を行う。却下済みは未対応へ戻せる。

### マスタ一覧

スキル名・別名検索、正規名、カテゴリ、別名、統合、再照合を提供する。再照合後は必要に応じて経験年数バックフィルを続けて実行する。

## 10. モック方針

`gh-pages/index.html` は2026-08-21時点で上記の主要画面と導線を反映済み。ダミーデータで操作感を確認するためのものでAPI保存は行わない。

- 実装のMaterial-UI構成、タブ順、主要文言、テーブル列、操作導線を優先する
- 古い要件・モック構成に合わせて実装から逆行させない
- 実装変更時は本書と [モック追従状況](../development/mock-sync-status.md) を同時更新する
