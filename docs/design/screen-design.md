# 画面設計

MVPで想定する画面構成を整理する。

- 作成日: 2026-08-03
- 更新日: 2026-08-04（入力補助・保存処理・職歴単位の勤怠提出元を反映）
- ステータス: ドラフト。確定仕様ではない。

---

## 1. 共通レイアウト

**Lavender（2way Manage system）の既存レイアウトをそのまま利用する。新規に作成しない。**

- 上部ヘッダー（AppBar「2way Manage system」）
- 左側サイドメニュー（Drawer 幅240px、PCは常時表示・SPはハンバーガー）
- メインコンテンツ（Container）

### サイドメニュー

FUKURO2.0とは別に、大項目「**SES**」を新設して以下を配置する。

```text
SES
  スキルシート
  案件一覧
```

配置位置・実装方法は [Lavender組み込み要件](../requirements/lavender-integration.md) を参照。

### スキルシートメニュー押下時の初期表示

左側サイドメニューの「スキルシート」を開いたときは、ログインユーザーの権限とスキルシート作成状況に応じて初期表示を出し分ける。

| 条件 | 初期表示 |
|------|----------|
| 管理者権限を持つユーザー | スキルシート一覧画面 |
| 管理者権限を持たないユーザー、かつ自分のスキルシート作成済み | 自分のスキルシート詳細画面 |
| 管理者権限を持たないユーザー、かつ自分のスキルシート未作成 | 新規スキルシート作成画面 |

非管理者ユーザーに対しては、自分以外のスキルシート一覧を初期表示しない。

### 前提

- PCブラウザを主対象とする
- **Material-UI v4** のコンポーネントを利用する（Lavender既存に準拠）
- パンくずはLavenderに既存の仕組みがないため、必要性を含めて工程1で判断する

## 3. スキルシート一覧画面

管理者権限を持つユーザーが「スキルシート」を開いた場合の初期表示画面とする。

### 表示項目候補

- 氏名
- 年齢
- 最寄駅
- 主なスキル
- 経験年数
- 就業状況
- 勤怠提出元
- 最終更新日時

就業状況は、職歴の「現在参画中」と終了年月から算出した値を表示する。選択肢は「稼働中」「待機中」「稼働中（終了予定あり）」とする。

勤怠提出元は、現在参画中の職歴、または最新の職歴の値を表示、検索対象にする。過去の全職歴を横断して勤怠提出元検索にヒットさせない。

### 操作

- 新規作成
- 詳細表示
- 編集
- Excelインポート

## 4. スキルシート詳細画面

管理者権限を持たないユーザーが「スキルシート」を開き、すでに自分のスキルシートを作成済みの場合は、この画面に自分のスキルシート内容を表示する。

### 表示セクション

- 基本情報
- スキルサマリー
- 資格
- 職歴一覧
- 自己PR

### 操作

- 編集
- PDF表示
- 複製して新規作成

### 表示方針

Excelの帳票をそのまま再現するのではなく、ブラウザで読みやすいカード、タグ、表形式を利用する。

職歴ごとに勤怠提出元（上位会社 / 参画中メンバー）を表示する。

最終更新日時は `yyyy-mm-dd hh:mm` 形式で表示し、秒は表示しない。

## 5. スキルシート編集画面

新規作成と既存スキルシート編集を兼用する。管理者権限を持たないユーザーが「スキルシート」を開き、まだ自分のスキルシートを作成していない場合は、新規作成状態でこの画面を表示する。

以下のタブまたはセクションに分ける。

1. 基本情報
2. スキル、資格
3. 職歴
4. 自己PR

職歴は複数件追加可能にする。

基本情報、就業・希望条件では以下の方針とする。

- 社員番号は半角英数字のみ入力できるようにする
- 氏名、フリガナには入力例を表示する
- 就業状況は入力項目として持たず、職歴から自動判定する
- 転職意向は入力項目から削除する
- 勤怠提出元は就業・希望条件ではなく、職歴ごとに入力する

スキル、資格では以下の方針とする。

- 年月入力は `yyyymm` の半角数字入力から `yyyy-mm` へ自動整形する
- スキルの最終利用にも入力例を表示する
- 資格の入力順は「資格名」「取得年月」「備考」とする

職歴では以下の方針とする。

- 開始年月、終了年月は `yyyymm` の半角数字入力から `yyyy-mm` へ自動整形する
- 現在参画中チェックの有無にかかわらず、終了年月は入力可能にする
- 現在参画中チェックを操作しても、入力済みの終了年月は削除しない
- 現在参画中チェックあり、かつ終了年月ありの場合は「稼働中（終了予定あり）」として扱う
- 勤怠提出元を職歴ごとに入力できるようにする

入力補助、入力チェックでは以下の方針とする。

- 日付、年月など桁数が確定する入力欄は、入力完了後に次の欄へ自動移動する
- 日付、年月は全角数字を半角へ変換し、区切り文字を自動入力する
- 13月、32日など成立しない日付、年月はエラー表示し、その欄に留める
- 職歴の開始年月と終了年月は、開始年月 <= 終了年月であることを検証する

保存処理では以下の方針とする。

- 新規作成、編集ともに保存できるようにする
- モック段階ではブラウザローカル保存で挙動確認し、本実装ではDB/API保存へ置き換える
- 保存時に最終更新日時を `yyyy-mm-dd hh:mm` 形式で更新する

### 下書き保存

スキルシート編集画面では、入力途中の内容を下書きとして扱う。

- 編集中は1分おきに下書きへ自動保存する
- 「保存する」押下時は、現在の入力データを正式保存し、下書きを破棄する
- 「キャンセル」押下時は、入力途中の内容を正式保存せず、下書きを破棄する
- 下書きが残っている状態で編集を中断した場合、次回編集画面を開いたときに下書き復元確認ポップアップを表示する
- 復元確認で「はい」を押下した場合、下書き内容を入力欄へ反映する
- 復元確認で「いいえ」を押下した場合、下書きを破棄し、正式保存済みデータを表示する

### 保存中ステータス表示

自動保存の状態は、**画面右下に固定表示**する（2026-08-04 決定）。

- 小さく表示し、編集操作を妨げない
- Material-UI v4 の Snackbar 等、既存コンポーネントで実現する
- 表示内容は「保存中」「保存しました（時刻）」程度にとどめる

### 下書き復元確認ポップアップ

| 操作 | 挙動 |
|------|------|
| はい | 下書きの内容を入力欄に反映する |
| いいえ | 下書きを破棄し、正式保存済みデータを入力欄に表示する |

## 9. 仮マッチング画面

**余力がある場合のみ作成する。**

- 案件情報
- 候補者一覧
- 一致スキル
- 一致件数
- 不一致スキル

案件の必須スキル文字列と、スキルシートに登録された技術情報を単純比較し、一致件数順に並べる。
