# 商流・年齢制限のLLM抽出 精度検証（decision-log #17/#18 確定用）

実施日: 2026-08-17／構成: 採用抽出構成と同一（gpt-5.6-luna・v2プロンプト・Structured Outputs）に商流・年齢の4項目を追加
対象: 検証済み実メールデータセット（v3c）の project 分類 171通（ローカル保管・リポジトリ外）

## 1. 方法

- 既存の抽出検証ハーネスの派生スクリプトで、案件抽出スキーマに `flow_text`（根拠原文）/`flow_limit`（正規化enum）/`age_limit_text`/`age_limit`（上限年齢int）を追加して全171通を抽出
- 正解ラベルが無いため、①キーワード事前スキャンとの突き合わせ（取りこぼし・過検出の候補洗い出し）②抽出根拠の原文と正規化値の全件目視レビュー（商流124件・年齢99件）の2段で評価

## 2. 結果サマリー

| 指標 | 商流 | 年齢制限 |
|---|---|---|
| 記載のあるメール（推定） | 約100/171通（58%） | 約85/171通（50%） |
| 抽出件数（案件単位） | 124件 | 99件 |
| 根拠原文の正当性（捏造・誤引用） | **0件** | **0件**（要員プロフィール年齢との混同も0） |
| 実質的な取りこぼし | 4〜6通（再現率 約95%） | ほぼなし（未検出は「制限なし」「数値なし」等の正当な棄却が大半） |
| 正規化の一貫性 | enum判定は一貫。ただし下記3の設計課題 | 約9割（「X0代まで」→X9/X0のゆらぎ約1割） |

- LLMは商流語彙を使わない制限（「貴社まで」「御社所属の方で」等）27通を正しく検出し、キーワード方式より明確に優位
- 不安定だった表現: 「商流はコントロールできる範囲で」（5回中2回のみ抽出）→ プロンプトに例示追加で対処
- 追いコスト: 取込1通あたり入力約2.2k/出力約0.6kトークン（既存抽出への項目追加のため増分は僅少）

## 3. 設計へのフィードバック（正規化スキーマ v1）

検証で判明した実態: 商流制限の約9割は「貴社まで」系で、当初enumの `first` が**性質の異なる3種を混在**させていた。マッチング判定（要員の 社員/BP 区分との突き合わせ）に直結するため、v1では以下に再設計する:

| enum（v1案） | 意味 | BP提案 |
|---|---|---|
| `own_only` | 貴社所属（正社員・契約社員）のみ。BP不可 | 不可 |
| `own_plus_support` | 貴社まで。ただし1社先は支援費対応等の条件付き可 | 条件付き可 |
| `first_ok` | 1社先まで可 | 可 |
| `second_ok` | 2社先まで可 | 可（深さ2まで） |
| `unrestricted` | 商流不問・制限なしと明示 | 可 |
| `unstated` | 記載なし | 不明扱い（足切りしない） |

- 個人事業主の可否は独立の頻出条件（「個人事業主可/不可」）のため、**別フラグ**（`freelance_ok`）として持つ
- 「エンド直案件」「元請け→弊社」等の**商流位置（浅さ）の自己申告は制限とは別概念**。検証では prime/second に不安定にマップされたため、制限のenumからは除外し、必要なら別フィールド（表示用）で扱う
- 年齢の正規化ルールに例示を明記する: 「40代まで」→49／「50代前半まで」→54／「50歳まで」→50
