# 同一案件グルーピング 精度検証（2026-08-19）

決定#30で「精度検証後に導入」として保留していた同一案件グルーピングについて、
dev DBの実データで判定基準を検証した記録。

## Summary

**確定した判定基準: 正規化タイトル一致 ＋ 勤務地の芯一致 ＋ 単価レンジ1.15倍未満（3条件AND）**

- 実データ1,556案件 → **619グループ**（重複率の高さから約60%圧縮）
- 目視で確定した「同名だが別案件」3件はすべて分離できる（既知誤統合0件）
- **必須スキル文は判定に使わない**（抽出ブレで同一案件を割るため。実証済み・後述）
- **タイトル類似度によるあいまい一致は採用しない**（閾値で真偽を分離できない。実証済み・後述）

決定#30が想定した「別営業から届いた同一案件」は5グループのみで、
重複の主因は**同一営業からの連投**（300グループ中295が送信元1社）だった。

### スキル文を判定に使ってはいけない理由

「タイトル＋勤務地」グループのうちスキル類似0.7を割るもの40件を確認したところ、
大半が**同一案件でありながら片方のスキル抽出が空 or 内容が異なる**ケースだった。

```
スキル類似0.00 単価比1.00 3件 | スマートフォンアプリの運営企業におけるUIデザイナー
   id=78    600000-None | UI/UX、Photoshop
   id=588   600000-None | UI/UX、Photoshop
   id=1143  600000-None | （空）

スキル類似0.00 単価比1.00 2件 | コーポレートITエンジニア
   id=86    None-600000 | （空）
   id=1141  None-600000 | Microsoft 365、Google Workspace
```

スキル条件を入れると、これらが別案件として分断される。抽出品質が安定するまで使えない。

### 単価を判定に使う理由

単価は「同一タイトル・同一勤務地の別ポジション募集」を分離できる。

```
スキル類似0.03 単価比1.20 14件 | 金融取引システムのハードウェア更改（西葛西駅）
   id=23  None-900000 | PostgreSQLのDBAとして、パフォーマンスチューニング、バックアップ・リカバリ…
   id=129 None-750000 | 以下の技術要素のいずれかについて基本・詳細設計書の執筆が可能な方：RHEL全般…
   id=144 None-750000 | 以下の技術要素のいずれかについて基本・詳細設計書の執筆が可能な方：HPサーバ機器、CISCO FCSW…
```

DBA枠90万 / RHEL設計枠75万 / HPサーバ枠75万 の3ポジション。単価比1.15閾値で分離される。

### タイトル類似度（あいまい一致）が使えない理由

正規化タイトルのbigram Jaccard 0.6以上のペア60件を全件目視した。
**真陽性と偽陽性が同じ類似度帯に混在し、閾値では分離できない。**

偽陽性（統合してはいけない）:
```
J=0.90  某大手クレジットカード基幹システムの保守A（りんかい線国際展示場駅）
     vs 某大手クレジットカード基幹システムの保守B（高田馬場）
J=0.86  金融系システム更改案件（要員A）75万 / （要員B）65万（ともに大崎）
J=0.83  大手自動車販売会社…フルスタックエンジニア（データ＋バックエンド / ＋フロント / ＋インフラ）
J=0.69  損保：代理店システムの開発（多摩センター） vs 共済：代理店システムの開発（市場前）
J=0.60  某金融機関NW設計・構築・運用 vs 某金融機関SV設計・構築・運用（ともに千里中央）
```

真陽性（統合すべき）:
```
J=0.95  大手EC運営企業における基幹受発注システム刷新に伴うブリッジエンジニア・PMO（＋「募集」の有無だけ）
J=0.92  【PM／PjM】AI領域におけるプロジェクトマネージャー募集案件 vs 【PjM】…
J=0.88  シナリオライター / AIキャラチャットボット… vs 【フルリモ】シナリオライター / …
J=0.83  Salesforce開発エンジニア（SE担当） vs Salesforce開発エンジニア（SE担当）※改訂版
```

差分が「接頭辞・接尾辞の追加」か「弁別子（A/B・要員A/要員B・管理/技術・地名）の違い」かの
区別が必要で、対称類似度では原理的に分離できない。
一方が他方を包含するかの判定も誤爆する:

```
[包含] 基地局関連情報管理システム開発 65万
    vs 基地局関連情報管理システム開発 開発補佐・交代枠 35万   ← 別枠
[包含] システム開発業務（西明石駅からバス20分）
    vs 販売物流システム開発業務（JR西大路駅）                ← 別案件
```

### 重複の実態

タイトル完全一致グループのサイズ分布（1,556案件 / 561グループ）:

```
1件:259グループ  2件:94  3件:78  4件:18  5件:34  6件:39  7件:8  8件:9  9件:6
10件:2  11件:4  12件:1  13件:1  14件:1  19件:1  22件:2  23件:1  28件:1
```

同一営業が件名だけ変えて連投している。最大グループ「VBA開発（現場直：弊社交代枠）」28件の例:

```
【8・9月/独占増員枠】VBA開発経験 / Excel VBA / 40〜50万
【即日or9月/注力VBA案件/50万円】VBA開発経験ある方/コミュニケーショ…
【即or9月/45万前後/VBA案件】Excel VBAの経験ある方探しています
【VBA案件/現場直/若手可能】Excel VBAの経験ある方募集
★現場直★【VBA案件/若手可能】Excel VBAの経験ある方募集
```

勤務地はすべて府中駅・単価40〜50万・必須スキルも同一で、`location`の差は表記ゆれのみ
（`府中駅（上位現場常駐）` / `府中駅 ※上位現場常駐` / 全角スペース違い）。
**location・単価を厳格一致で判定すると同一案件を分断する**ため、勤務地は駅名・地名の芯だけ、
単価はレンジ比較（1.15倍未満）で扱うこと。

## Source

- 出所: `ses` スキーマ（`dev.2-way.co.jp:3306`）を pymysql + `ssl_disabled=True` で直接読み取り
- 取得日時: 2026-08-19 16:44 JST。`projects` 1,556件 + 紐づく `mails` を結合してローカルダンプ
- 信頼度: 高（実データ全件。誤統合判定は目視確認）
- 有効期限: **要再検証**。本データは4日分・送信元120ドメインのみ。取り込み対象アカウントや
  送信元の顔ぶれが変わった場合、および案件情報の抽出ロジック（LLM）を変更した場合は再評価すること
- 検証時点の運用データ: `matchings` 3件 / `proposals` 4件（ほぼ空。状態設計の変更コストが低い時期）
