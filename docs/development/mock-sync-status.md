## 3. モックで簡略化しているもの

以下は画面構成と導線を確認できるが、実処理は行わない。

| 機能 | モックでの扱い |
|---|---|
| API保存 | Toast表示と画面遷移のみ。DBへは保存しない |
| メール取り込み | 実行中表示、ポーリング、Gmail取得、LLM抽出は再現しない |
| マッチング計算 | ダミー点数・条件比較を表示。サーバー計算、キャッシュ、グルーピングは実行しない |
| PDF表示 | ブラウザ印刷用レイアウトを表示。サーバー生成は行わない |

## 4. 実装変更時の更新ルール

1. Lavenderのルートと対象コンポーネントを確認する
2. 見出し、タブ順、入力項目、一覧列、状態、主要ボタンをモックへ反映する
3. [画面設計](../design/screen-design.md) を同時更新する
4. 構文チェックと主要導線のDOMテストを実行する
5. この表の状態と簡略化範囲を更新する

古い要件記述と実装が異なる場合は、明示的な将来変更指示がない限り最新実装を優先する。

## 5. 保留中の将来変更

修正タスクリストC8に、マッチング一覧の昇格ボタンとマッチング結果の承認操作を削除する案が追記されている。2026-08-21時点では実装・モックとも現行フロー（候補昇格、承認、未提案、提案作成）を表示している。C8実装時に本書、画面設計、API契約、データモデル、モックをまとめて更新する。
