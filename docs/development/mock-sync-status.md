- **起点コミット**: `66cb1dd` docs: add attendance submission source requirement

#### 要件の内容

- 職歴ごとに「勤怠提出元」を追加する

- **起点コミット**: `ae0ea65` docs: add skill sheet initial routing requirements
- **要件の出典**:
  - [MVP要件定義 2. システム全体方針](../requirements/mvp-requirements.md)

#### 要件の内容

左側サイドメニューの「スキルシート」を開いたとき、ログインユーザーの状態に応じて初期表示を出し分ける。

| 条件 | 初期表示 |
|------|----------|
| 管理者権限を持つユーザー | スキルシート一覧 |
| 管理者権限を持たないユーザー、かつ自分のスキルシート作成済み | 自分のスキルシート詳細 |
| 管理者権限を持たないユーザー、かつ自分のスキルシート未作成 | 新規スキルシート作成 |

#### モックに必要な修正

| 画面 | 修正内容 |
|------|---------|
| スキルシートメニュー | 管理者／非管理者／未作成ユーザーの3パターンを切り替えて確認できる状態を追加 |
| スキルシート一覧 | 管理者ユーザー向けの初期表示であることを表現 |
| スキルシート詳細 | 非管理者・作成済みユーザーの初期表示として確認できる導線を追加 |
| スキルシート編集 | 非管理者・未作成ユーザーの新規作成初期表示として確認できる導線を追加 |

#### 状況

**対応中**（2026-08-04時点）。モック単独では完結せず、**Lavender既存の権限実装と併せて設計する**。

#### 前提となる作業（Lavender／API側）

現在のLavenderは、ログイン状態は持っているが**ログインユーザーの権限情報をフロント側で保持していない**。
そのため「権限で初期表示を出し分ける」には、以下がSES機能の実装より前に必要になる。

1. ログインAPIのレスポンスに権限情報を含める
2. フロント側のログイン状態に権限情報を保持する
3. 権限に応じた画面制御を行えるようにする

また、権限制御はフロントの出し分けだけでは担保できない（APIを直接呼べば素通りする）ため、
**API側でも同等の制御を行う**こと。

> 権限体系の詳細な調査結果・設計方針は社内メモで別途管理している。
> 本リポジトリは公開設定のため、認証・認可の内部仕様はここには記載しない。

### #4 下書き自動保存・復元確認

- **起点コミット**: `3b4f1df` docs: add skill sheet draft autosave requirements
- **要件の出典**:
  - [スキルシート要件 7. 下書き保存](../requirements/skill-sheet-requirements.md)
  - [画面設計 5. スキルシート編集画面](../design/screen-design.md)

#### 要件の内容

スキルシート編集中は、1分おきに下書きへの自動保存を行う。正式保存またはキャンセル時は下書きを破棄する。下書きが残った状態で編集を中断した場合、次回編集画面を開いたときに下書き復元確認ポップアップを表示する。

| 操作 | 挙動 |
|------|------|
| 保存する | 現在の入力データを正式保存し、下書きを破棄する |
| キャンセル | 入力途中の内容を正式保存せず、下書きを破棄する |
| 復元確認: はい | 下書き内容を入力欄に反映する |
| 復元確認: いいえ | 下書きを破棄し、正式保存済みデータを入力欄に表示する |

#### モックに必要な修正

| 画面 | 修正内容 |
|------|---------|
| スキルシート編集 | 1分おきの下書き自動保存状態を表現 |
| スキルシート編集 | 保存・キャンセル時に下書きが破棄される挙動を表現 |
| スキルシート編集 | 下書きが残っている場合の復元確認ポップアップを追加 |

#### 決定事項（2026-08-04）

| 論点 | 決定 |
|------|------|
| 下書きの保存先 | **DBに保存する**（ブラウザローカルではない） |
| 保持単位 | **ユーザー×スキルシート単位**。JSONで丸ごと保持 |
| 保存中ステータスの表示 | **画面右下に小さく固定表示**する |
| テーブル | `skill_sheet_drafts` を新設 → [データモデル 2.8](../design/data-model.md) |

管理者が他人のスキルシートを編集した場合、下書きは編集した本人のものとして保持する。

- 新規作成中（対象スキルシートが未確定）の下書きをどう一意に識別するか
- 自動保存API呼び出しの失敗時に、画面上でどう扱うか

### #5 入力補助、保存処理、表示項目整理

- **起点コミット**: 未コミット（2026-08-04の要件更新）
- **要件の出典**:
  - [スキルシート要件](../requirements/skill-sheet-requirements.md)
  - [画面設計 3・4・5章](../design/screen-design.md)

#### 要件の内容

- 日付、年月入力は半角数字のみを実入力とし、区切り文字を自動入力する
  - 生年月日: `yyyymmdd` → `yyyy-mm-dd`
  - 開始年月、終了年月、取得年月、最終利用: `yyyymm` → `yyyy-mm`
- 入力完了後、自動的に次の欄へ移動する
- 13月、32日など成立しない年月、日付はエラー表示し、その欄に留める
- 職歴の開始年月と終了年月は、開始年月 <= 終了年月であることを検証する
- スキルの最終利用に入力例を追加する
- 社員番号は半角英数字のみ入力できるようにする
- 資格の入力順を「資格名」「取得年月」「備考」にする
- 就業・希望条件から「転職意向」「就業状況」を削除する
- 就業状況は職歴から自動判定する
  - 現在参画中チェックあり、終了年月なし: 稼働中
  - 現在参画中チェックあり、終了年月あり: 稼働中（終了予定あり）
  - 現在参画中チェックなし: 待機中
- 現在参画中チェックの有無にかかわらず、終了年月は入力可能にする
- 現在参画中チェックを操作しても、入力済みの終了年月は削除しない
- 新規作成、編集の保存処理を可能にする
- 最終更新日時は `yyyy-mm-dd hh:mm` 形式で表示する

#### モックに必要な修正

| 画面 | 修正内容 |
|------|---------|
| スキルシート一覧 | 勤怠提出元検索を最新職歴のみ対象にする。就業状況検索の選択肢を3種類にする。最終更新日時を分まで表示する |
| スキルシート詳細 | 職歴単位の勤怠提出元、資格順、算出した就業状況を表示する |
| スキルシート編集 | 入力補助、入力チェック、保存処理、不要項目削除、資格順変更、現在参画中チェックの挙動変更を反映する |

#### 未確定のため要判断

- 本実装時の保存API、DBテーブル、バリデーション責務の分担
- Excelインポートで不正値があった場合のエラー表示方法
