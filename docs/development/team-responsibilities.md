# 開発体制と役割分担

3人開発を前提に、担当範囲と開発工程を整理する。

- 作成日: 2026-08-03
- 更新日: 2026-08-21（最新実装の6メニューと担当範囲を反映）
- ステータス: ドラフト

> **実装状況（2026-08-21）**: メール取り込み、メンバー／スキルシート、マッチング、提案、
> スキルマスタの主要機能と画面導線は実装済み。
> 詳細は [実装現状の記録](implementation-status.md) を参照。

> **前提**: 本システムはLavenderの1機能として追加する。フロントエンドの初期構築・認証・
> 共通レイアウトの整備は不要になり、担当Aの作業量が減る。
> 詳細は [Lavender組み込み要件](../requirements/lavender-integration.md) を参照。

---

## 1. 分割方針

技術レイヤー単位ではなく、**機能単位**で分ける。

| 担当 | 領域 |
|------|------|
| 担当A | 共通基盤、DB、API |
| 担当B | メンバー管理、スキルシート管理 |
| 担当C | 案件メール取り込み、要員メール取り込み、マッチング、提案管理、スキルマスタ |

---

## 2. 担当A：共通基盤、DB、API

### 責任範囲

- **Lavenderへの大項目「SES」追加**（`src/index.tsx` のメニュー・ルート定義）
- DB設計
- マイグレーション
- 共通API
- ファイル保存方式
- 共通エラーハンドリング
- 担当B、Cとのインターフェース調整
- メンバー詳細、マッチング、提案管理をまたぐ共通API設計

### 方針変更による差分

- フロントエンドのプロジェクト初期構築・ローカル開発環境整備は**不要**（Lavender既存を利用）
- 代わりに、**`src/index.tsx` の競合回避**が必要。担当B・Cが同じファイルを触るため、
  担当Aが先にSES大項目とルートの雛形を入れてからB・Cが着手する

### 進め方

先にOpenAPIやサンプルJSONを作成し、担当B、CがAPI完成を待たずに作業できるようにする。

---

## 3. 担当B：メンバー管理、スキルシート管理

### 責任範囲

- メンバー一覧
- メンバー詳細 info タブ
- ~~既存Excelの構造解析／Excelインポート~~ → **中止**（2026-08-16決定）
- メンバー詳細 スキルシートタブ
- スキルシート新規作成
- スキルシート編集
- 職歴管理
- スキル管理
- 資格管理
- 自己PR管理
- PDF表示または印刷用画面

---

## 4. 担当C：案件メール取り込み、要員メール取り込み、マッチング、提案管理

### 責任範囲

- メールサービス接続
- 対象メール検索
- メール本文取得
- 案件情報抽出
- 案件DB登録
- 要員情報抽出
- 要員DBまたはメンバー候補DB登録
- 重複登録防止
- 取り込み履歴
- 案件メール一覧
- 案件詳細、編集
- 要員メール一覧
- 要員詳細、編集
- マッチング一覧
- メンバー詳細 マッチングタブ
- 提案管理一覧
- メンバー詳細 提案タブ
- スキルマスタ、登録待ちスキルの仕分け、再照合

---

## 5. 開発工程

### 工程1：仕様固定

3人で以下を決める。

> 決定済み: バックエンドAPIは既存の **thyme** に相乗りし、DBは **SES用スキーマを新設**する。
> SESメニューとルートは権限定義で制御し、メンバー詳細の初期タブは遷移元に応じて指定する。

- スキルシート項目
- 案件項目
- 対象メールサービス
- 対象メールの判定条件
- API一覧
- 画面一覧
- サンプルJSON

### 工程2：共通基盤

| 担当 | 作業 |
|------|------|
| A | Lavenderへのメニュー・ルート雛形追加、DB、API |
| B | 画面モック（Excel解析検証は中止により不要） |
| C | メール取得検証、案件画面モック |

※ 担当Aの雛形追加が完了してから、担当B・Cが画面実装に着手する（`src/index.tsx` の競合回避）。

### 工程3：機能実装

| 担当 | 作業 |
|------|------|
| A | 共通API、DB、保存処理 |
| B | スキルシート管理（Excel取り込みは中止） |
| C | メール取得から案件登録まで |

### 工程4：結合

- スキルシート画面とAPIの結合
- 案件画面とAPIの結合
- メール取り込み確認
- 重複登録防止確認
- 編集内容の保存確認

### 工程5：マッチング・提案管理

- 案件と要員またはメンバーのマッチング結果を一覧化する
- マッチング一覧からメンバー詳細のマッチングタブへ遷移できるようにする
- 承認済みマッチングを提案管理一覧へ連携する
- 提案管理一覧からメンバー詳細の提案タブへ遷移できるようにする
