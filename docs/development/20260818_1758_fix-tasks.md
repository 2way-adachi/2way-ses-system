      畳み損ねは現状と同じ状態にしかならないという非対称性による
    - グループは `projects.group_id` に**永続化**する（都度計算にしない）。承認・見送りの状態を
      グループに紐づけるため
    - 承認・見送り・提案は**グループ単位**に集約する。`matchings` 3件・`proposals` 4件でほぼ空の
      いまなら移行コストがほぼゼロ
  - **`region`（F1の地方区分）をグルーピングに使わないこと**。地方粒度では
    「UIデザイナー／六本木一丁目・60万」と「UIデザイナー／外苑前・50万」が同じ関東になり別案件を畳む
  - 副次効果として、マッチング評価の母集団が1,556→619件になる。メンバー詳細マッチングタブの
    都度計算約1.5秒の短縮が見込めるため、**実装前後で応答時間を計測して記録すること**
