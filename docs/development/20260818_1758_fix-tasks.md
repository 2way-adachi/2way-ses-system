- [x] **A5. ステージングでSES系APIに「パラメーター不正」WARNが多発** — **完了**（thyme `1666abe`。実害なし・ログノイズのみと確定）
  - **真因は `/ses/**` がREST形式だからではなかった**。Lavenderのses系axiosクライアント（`api/ses/client.ts`）が
    **フラットな `headers` に `Content-Type: application/json` を設定**しており、axios 0.21.1 の仕様で

  - 副作用として、ボディが空のPOSTは従来のWARNから「ボディなし」のinfoになる。chunked転送のPOSTは
    リクエストログが出なくなる（axiosの通常のJSON POSTはContent-Lengthを付けるため現状は該当なし）

    「パラメーター不正」を**299件**出力している

    レスポンス自体が異常か（実害があるか）はログからは判別できていない

  - 2026-08-20 ステージング実機で発見。タスクリスト外（決定#36の2フレーム化以降の症状）

## M. OpenAI呼び出しのレート制御と並列数の見直し（2026-08-21 人間指示・決定#43）

2026-08-19に並列4で429を踏み、暫定で2へ引き下げたまま。**もう少し上げたい**というのが起点。

### 調査済みの前提（推測ではなく実測・コード確認済み）

- **上限を決めているのは並列数ではなくTPM**。実測 TPM 200,000 ÷ 1リクエスト約6,000トークンで
  **毎分約33リクエストが天井**。並列数は「どれだけ速く天井にぶつかるか」を決めるだけで、
  ペーシング無しに並列だけ上げるとバーストが強くなり429を踏む頻度が上がる
- **適正並列数 N = 33 × T ÷ 60**（T = 1リクエストの所要秒数）。
  T=5秒ならN≈3 / T=10秒ならN≈6 / T=20秒ならN≈11。**T が未計測のため現状では決められない**
- 現状のバックオフは**スレッド単位**（`OpenAiMailExtractor.waitBackoff()` が `Thread.sleep`）。
  429を踏んだ1本が待つ間も他スレッドが投げ続けるため、**全体の投入レートが下がらない**。
  2026-08-19にリトライ5回・累計62秒粘って全滅したのはこれが理由
- 並列は `MailImportService` の `Executors.newFixedThreadPool(parallelism)`（固定プール）
- レート制限ヘッダが使える（[OpenAI API仕様](../../../thyme/2way-thyme/docs/api_spec/openai-api.md) §レート制限）:
  `x-ratelimit-remaining-tokens` / `x-ratelimit-reset-tokens` / `Retry-After`。
  仕様書自身が「remaining-tokens を監視して並列数を動的に絞ると429を踏む前に減速できる」と記載

- [x] **M1. 429時の共有クールダウン** — **完了**（thyme `68ac257`。OpenAiRateGateをBean化して共有。Retry-After下限+ジッター。IOExceptionはレビュー指摘によりスレッドローカル待機に分離）

  - `Retry-After` は公式の指示どおり**最小待機時間**として扱い、さらに小さなランダム遅延を加える

## V. メンバー編集のフリガナ入力がIME変換中に壊れる（2026-08-21 人間指摘・調査済み）
