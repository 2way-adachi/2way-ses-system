# 2way-ses-system

SES事業向けの補助システム。スキルシートと案件情報をWeb上で一元管理する。

**本システムは独立サービスではなく、既存の管理画面Lavender（2way Manage system）の1機能として追加する。**
Lavenderのサイドバーに、FUKURO2.0とは別の大項目「SES」を新設し、その配下に
「案件メール一覧」「要員メール一覧」「メンバー一覧」「マッチング一覧」「提案管理一覧」「スキルマスタ」を配置する。
スキルシートは独立メニューにせず、メンバー詳細内のタブとして扱う。

→ [Lavender組み込み要件](docs/requirements/lavender-integration.md)

## システム概要

現在、スキルシートはExcel、案件情報はメールで管理されており、以下の課題がある。

- 情報がファイルやメールに分散している
- 最新版が分かりにくい
- 検索や一覧化が難しい
- 案件と人材情報を横断的に利用できない
- スキルシートの更新や共有に手間がかかる

本システムは、これらの情報をDBへ格納し、ブラウザ上から管理可能にする。

## MVPの目的

MVPの中心は次の軸とする。

1. 案件メールからの案件情報格納自動化
2. 要員メールからの要員情報格納自動化
3. メンバー情報とスキルシートの管理
4. 案件と要員のマッチング管理
5. マッチング結果からつながる提案管理

## 主要機能

### メンバー・スキルシート管理【スキルシートは実装済み】

- メンバー一覧・新規登録・編集・詳細
- メンバー詳細（基本情報／スキルシート／マッチング／提案状況のタブ）
- スキルシートの表示、新規作成、編集（下書き自動保存・復元含む）
- 経歴、スキル、資格、自己PRの管理
- PDF表示（印刷用HTML＋ブラウザ印刷。職務経歴書レイアウト）
- ~~既存Excelからの初期取り込み~~ → **中止**（2026-08-16決定）

### マッチング・提案管理【実装済み】

- 要員と案件のマッチング（スキルマスタ、勤務地、同一案件グルーピングを利用）
- マッチング一覧・結果詳細・候補者のメンバー昇格・承認
- 提案管理（6段階の進捗表示、更新フォーム、メンバー詳細タブとの連携）

### 案件・要員メール管理【実装済み】

- メールサービスとの接続、対象メールの取得
- 案件情報・要員候補の抽出とDB登録（重複登録防止）
- 案件・要員候補の一覧、詳細、編集
- メール取り込み履歴の確認

## MVP対象外

- 高精度なAIマッチング、機械学習
- Excelインポート全般（2026-08-16中止）、Excelへの再出力
- 請求 / 契約 / 勤怠 / 営業管理
- 詳細な承認ワークフロー、詳細な変更履歴比較、複雑な権限管理
- メールへのPDF自動添付、リアルタイムメール受信

## 基本方針

- **Lavenderの1機能として追加する。** 独立サービスとして作らず、認証・共通レイアウトは既存を利用する
- **DB上の情報を正本とする。** スキルシートはブラウザ上で新規作成、参照、編集する
  （既存Excelの内容はブラウザ上での新規作成で移行する）
- **外部提出、メール添付、印刷が必要な場合はPDFを利用する**

## 確定事項

| 項目 | 決定 |
|------|------|
| フロントエンド | Lavender既存（React 17 / TypeScript / Material-UI v4 / Redux Toolkit） |
| バックエンドAPI | 既存の **thyme**（Spring Boot）に相乗り |
| DB | fukuroに同居させず、**SES用スキーマを新設**（MySQL） |
| 認証・ユーザー管理 | Lavender既存のログイン機構 |
| 共通レイアウト | Lavender既存のAppBar・Drawer・Container |
| 就業状況 | 入力させず、職歴から自動判定 |
| 勤怠提出元 | **スキルシート単位で保持**（2026-08-12に職歴ごとから変更）。任意入力 |
| 下書き | DBに保存。ユーザー×スキルシート単位、JSONで保持 |
| 保存中ステータス | 画面右下に小さく固定表示。失敗時は黙って再試行 |
| 自動保存の適用範囲 | 新規作成中は行わない。手動保存後の編集から有効 |
| SESメニュー | 権限定義を一元管理し、利用可能な画面のみ表示 |
| メンバー詳細タブの初期表示 | 遷移元（マッチング一覧／提案管理一覧）に応じて表示タブを指定（2026-08-17。権限による出し分けは廃止） |
| PDF生成方式 | 印刷用HTML＋ブラウザ印刷（2026-08-05実装） |
| Excelインポート | **中止**（2026-08-16決定） |
| 本リポジトリの役割 | 要件文書と画面モックのみ。実装コードは置かない |
| パス命名規約 | ケバブケースに統一（既存パスの改名はしない） |

## 今後の変更候補

- マッチング一覧の「候補者をメンバーへ昇格」と、マッチング結果の承認ボタン／承認状態を廃止し、以降の進捗は提案ステータスへ一本化する案（C8）。現行実装とモックには昇格・承認が残っている。

## 決定済み

- matchings設計・承認UI: 承認状態のみの薄いテーブル。見送り理由は任意。操作はメンバー詳細のマッチングタブ。
  提案は自動作成せず「提案を作成」＋未提案バッジ（[データモデル 5章](docs/design/data-model.md)）

- DB構成: `members` は新設せず `personnel` を拡張、`matchings` は承認状態のみの薄いテーブル、
  スコアは都度計算（[データモデル 3章](docs/design/data-model.md)）
- 提案ステータス: 下書き／提案メール送信済み／面談／先方返信待ち／完了／見送り／取下げ。
  面談は1値＋実施済み面談回数カラム。`next_action_date` を追加
- 一般ユーザーにも案件一覧の参照を許可（許可範囲は一元管理して切り替え容易に）
